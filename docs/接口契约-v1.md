# 云端接口契约 v1

当前实现状态：**模拟后端已实现，真实千匠问天未联调**。模拟后端与真实后端应使用同一套版本化接口。生产环境必须移除模拟用户切换和固定模拟令牌。

## 通用规则

- Base URL 示例：`https://api.example.com/api/v1`。
- 业务用户身份：服务端从已验证登录态解析，不信任请求体中的 `user_id`、`owner_id`、`tenant_id`。
- 设备身份：`Authorization: Bearer <device_token>`，可轮换、可撤销、仅能访问所属用户资源。
- 所有写接口要求幂等语义；任务创建使用用户范围内唯一 `idempotency_key`，结果回传使用 `report_key`。
- 任务执行实例使用 `attempt_id`；旧 attempt 不得覆盖新 attempt。
- 错误格式：`{"error":{"code":"...","message":"...","details":{}}}`。
- 默认超时：客户端 15 秒；网络错误可重试读取/领取类请求，提交授权和结果回传必须带幂等键。
- 状态枚举：`queued / claimed / downloading / uploading / ready_to_submit / submitting / submitted / needs_user_action / outcome_unknown / failed / cancelled`。
- `submitted` 表示平台已接收或适配器确认提交，不等于公开发布成功。

## 1. 申请绑定

`POST /bindings`

调用方：未绑定桌面助手。

请求：`{"device_name":"DESKTOP-01","assistant_version":"0.1.0-test"}`

响应：`{"binding_id":"bind_...","code":"123456","poll_token":"poll_...","expires_at":"...","confirm_url":"..."}`

规则：绑定码 10 分钟过期、单次使用、最多 5 次确认尝试；`poll_token` 独立于绑定码。

## 2. 网页确认绑定

`POST /bindings/{binding_id}/confirm`

调用方：已登录业务用户。

请求：`{"code":"123456"}`

响应：`{"ok":true,"device_id":"dev_..."}`

权限：服务端从登录态解析业务用户。确认后生成设备凭证，但不在网页响应中返回设备凭证。

## 3. 查询绑定结果

`POST /bindings/{binding_id}/poll`

调用方：未绑定桌面助手，凭 `poll_token`。

请求：`{"poll_token":"poll_..."}`

响应：pending：`{"status":"pending"}`；approved：`{"status":"approved","device_id":"dev_...","device_token":"devtoken_..."}`。

规则：设备凭证仅允许成功下发一次，之后轮询返回 `consumed`。

## 4. 设备心跳

`POST /devices/heartbeat`

调用方：设备。

请求：`{"assistant_version":"0.1.0-test"}`

响应：`{"ok":true,"server_time":"..."}`

权限：撤销设备返回 401。

## 5. 同步平台账号元数据

`POST /accounts/sync`

调用方：设备。

请求：`{"accounts":[{"account_key":"localacct_...","platform":"douyin","nickname":"本机备注","platform_identity":"平台内唯一标识","status":"logged_in","capabilities":{},"last_check_at":"..."}]}`

响应：`{"accounts":[{"account_key":"localacct_...","account_id":"acct_..."}]}`

规则：不同步 Cookie、密码或完整登录状态；昵称仅作展示，不作为路径或身份凭证。

## 6. 创建发布任务

`POST /tasks`

调用方：业务用户。

请求字段：`device_id, account_id, platform, title, description, topics[], cover_ref?, material_id, idempotency_key`。

权限：设备、账号、素材都必须属于当前用户；账号设备与平台必须匹配。

幂等：同一用户重复提交同一 `idempotency_key` 返回原任务，不重复创建。

## 7. 原子领取任务

`POST /tasks/claim`

调用方：设备。

响应：`{"task":null}` 或任务对象。任务对象包含 `attempt_id`、租约、短期素材下载地址、内容摘要/版本。

规则：服务端事务内将 `queued` 改为 `claimed`；并发请求最多一个成功。每台设备首版同时只执行一个任务。

## 8. 续租

`POST /tasks/{task_id}/lease`

请求：`{"attempt_id":"attempt_...","manual_hold":false}`

人工接管期间 `manual_hold=true`，服务端延长但不能因为普通租约到期盲目派给其他设备。

## 9. 上报进度

`POST /tasks/{task_id}/progress`

请求：`{"attempt_id":"...","status":"uploading","progress":50,"message":"...","error":null}`

权限：任务必须属于该设备和当前 attempt。终态任务拒绝进度更新。

## 10. 保存提交意图

`POST /tasks/{task_id}/submission-intent`

请求：`{"attempt_id":"...","content_version":"...","account_id":"..."}`

规则：只表示准备提交，不代表已点击发布。内容版本和目标账号不匹配时拒绝。

## 11. 请求提交授权

`POST /tasks/{task_id}/submit-authorization`

请求：`{"attempt_id":"...","content_version":"..."}`

响应：`{"submit_token":"submit_...","expires_at":"..."}`

规则：仅 `ready_to_submit`、租约有效、未取消、当前 attempt、内容版本一致时可授权。进入授权后任务变为 `submitting`，同一有效窗口不重复授权。

## 12. 回传结果

`POST /tasks/{task_id}/result`

请求：`{"attempt_id":"...","report_key":"...","outcome":"submitted|failed|outcome_unknown|cancelled","evidence":{},"error":null,"submit_token":"..."}`

`evidence` 约定字段（适配器可选回传）：

- `submit`：提交动作证据（选择器、点击时间）。
- `success_pattern` / `failure_pattern` / `redirect`：结果识别依据。
- `platform_item_id`：平台返回的作品唯一标识（如抖音 `item_id`，来自发布接口响应捕获）；`platform_item_id_field` 记录字段名，`publish_api` 记录来源接口。未捕获到时为 `null` 并附 `platform_item_id_note`。

幂等：同一 `task_id + attempt_id + report_key` 重复回传返回原结果。

规则：提交中回传 `submitted` 必须带有效 `submit_token`。旧 attempt 返回 409。进入 `submitting` 后断网或崩溃只能回传 `outcome_unknown`，不能自动二次提交。

## 13. 取消任务

`POST /tasks/{task_id}/cancel`

调用方：业务用户。

规则：`submitting` 及终态不可取消；未提交任务可取消。

## 14. 查询及处理结果待核实

- `GET /tasks/needs-review`
- `POST /tasks/{task_id}/review`

调用方：业务用户。人工确认平台已接收或失败，并记录说明。

## 素材下载

`GET /materials/{material_id}/download?access_token=...`

素材地址必须短期授权。生产模式校验协议、域名解析、重定向、内容类型、大小和 SHA-256，并阻止本机/内网地址。本地模拟服务仅在开发配置允许回环地址。

## v1.1 修订（2026-10-09，验收审计第一批修复）

### 绑定与心跳携带业务主体

- `POST /bindings/{binding_id}/poll` 批准响应新增 `user_id`：设备据此计算本机主体分区键 `subject_key = sha256(service_url + "|" + user_id)` 前 24 位十六进制。
- `POST /devices/heartbeat` 响应新增 `user_id`：用于旧版本回填与主体漂移检测；漂移时助手停止任务执行并要求重新绑定。
- 换绑语义：本机已存在绑定时，助手先停止并等待执行结束（最长 90 秒，超时返回 409 `worker_busy`），关闭全部接管的浏览器，再写入新绑定。本机账号、任务、浏览器 profile 按 `subject_key` 隔离，旧主体数据保留但不可见、不同步。

### 任务状态转换表（服务端强制）

- 单调阶段：`claimed < downloading < uploading < ready_to_submit`，设备进度只允许同级刷新或前进。
- `needs_user_action`：可从四个执行阶段进入，人工处理后只能回到 `uploading` 或 `ready_to_submit`。
- `submitting`：仅由提交授权进入；该状态下拒绝一切进度上报。
- 终态 `submitted / failed / outcome_unknown / cancelled`：拒绝一切设备进度与结果上报。
- 非法转换返回 409 `invalid_transition`；终态后上报返回 409 `task_terminal`。

### 提交授权一次性

- 每个 `attempt_id` 仅发放一次提交授权；`submit_authorized_at` 已存在即返回 409 `submit_already_authorized`，令牌过期不再重发。授权过期或提交中断后必须走结果核实，不得再次发布。

### 结果回传规则

- `submitted` 仅当任务处于 `submitting` 且 `submit_token` 有效时接受。
- `submitting` 状态下上报 `failed / outcome_unknown` 需要有效 `submit_token`；令牌已过期时放行（覆盖客户端提交中断后重启恢复）。
- 相同 `report_key` 重复上报：结果内容与首次一致才返回幂等成功，不一致返回 409 `report_conflict`。
- `outcome_unknown` 转为 `submitted / failed` 只能走 `POST /tasks/{id}/review` 人工核实。
