## 抖音作品唯一标识回传（2026-10-14，v0.2.0-test）

问题：发布后云端 evidence 只有成功文案与跳转 URL，无平台作品唯一标识。

真机观测（探针 scripts/probe-network-capture.js 挂载 CDP 网络域）：发布点击后平台调用 POST \`/web/api/media/aweme/create_v2/\`，响应 \`{"item_id":"7696484688709324047","status_code":0}\` —— 平台在发布响应中返回唯一标识。

实现：
- \`ManagedBrowser.startResponseCapture(patterns)\`：按 URL 子串监听 JSON 响应并取回响应体，stop 时注销监听。
- 适配器 \`submitOnce\` 点击前按配置 \`publishApiPatterns\`（抖音：\`/web/api/media/aweme/create\`）开启捕获；\`verifyResult\` 判定后从响应中提取 \`resultIdFields\`（抖音：\`item_id\`，仅采信 status_code=0），合并进 evidence：\`platform_item_id / platform_item_id_field / publish_api / publish_api_status\`；未捕获到则为 null 并附 note。契约见 docs/接口契约-v1.md 第 12 节。

真机复测：任务 task_LCNs-w8l4ewF0IMJhjeKhQ 自动闭环 submitted，云端 evidence 实收 \`platform_item_id: "7696486120457669931"\`（与首次发布的 7696484688709324047 不同，确认唯一）。

回归：\`npm test\` 34 通过（新增 2 项：evidence 合并作品标识、捕获开关与过滤）。

待办：视频号/小红书的发布接口与 ID 字段需在各自下次真机发布时用探针校准后填入 publishApiPatterns/resultIdFields。
