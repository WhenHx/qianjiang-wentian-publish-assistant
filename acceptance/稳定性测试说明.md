# 稳定性测试说明（0.1.7-test）

## 启动方式

```powershell
cd E:\问天\zuomianzhushou

# 终端 1：模拟云端（任务来源）
npm run start:mock

# 终端 2：CDP 模式助手核心（真实操作浏览器）
node src/assistant/main.js --config config/assistant.cdp-local.json

# 终端 3：桌面界面（连 CDP 实例）
powershell -NoProfile -ExecutionPolicy Bypass -File apps/desktop-wpf/Assistant.ps1 -Config config\assistant.cdp-local.json
```

浏览器测试控制台：http://127.0.0.1:8780/console（绑定确认、传素材、建任务、结果核实都在这里）。

默认安全姿态：自动化真实操作浏览器，但**停在最终提交前**（ready_to_submit），需在桌面端手动"执行一次提交"。

## 建议的稳定性测试项

1. **连续多任务**：同一账号连续派 3~5 个任务，观察任务互斥（同时只执行一个）、ready_to_submit 保持、提交后自动领下一个。
2. **长时间挂机**：助手运行 1 小时以上，观察心跳、租约续期（接管中的任务每 30 秒续租）、内存占用。
3. **会话过期**：在平台后台退出登录或等待会话过期，下一个任务应进入"需要人工处理"而不是乱发。
4. **换绑切换**：解绑后绑定另一个业务用户，确认旧账号/任务不可见（F01）。
5. **中途断网**：任务执行中断网，确认进入 `outcome_unknown` 或失败，恢复后不自动重发。
6. **助手重启**： ready_to_submit 保持的任务在助手重启后需重新接管（F10 恢复闭环是已知未修复项，观察行为是否符合文档描述）。
7. **提交后识别**：三个平台各发一条，确认跳转后自动识别 `submitted`（抖音 content/manage、视频号 post/list、小红书 publish/success）。

## 已知边界（测试时预期内）

- 上传完成不做平台侧转码校验（F05 残余）：以页面预览为准。
- 快手账号被封未修复提交链路，当前不要使用快手平台。
- 重启后 held 任务不自动恢复（F10），需重新派任务。
- 平台页面改版会导致选择器失效：表现为任务进入"需要人工处理"或身份核验拦截，属安全方向失败。
